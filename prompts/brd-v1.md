# BRD v1

Business requirements document for version 1. Start here before code.

```text
I want to solve [Problem] with a [app / Chrome extension / mobile app].

Act as an experienced product manager. Create a concise business requirements
document in Markdown for version 1 of this idea.

Your document must use these headings and answer each question explicitly:

1. Who is the user? — primary persona for v1
2. What painful job are they doing? — current workflow and friction
3. What changes after success? — concrete outcome for the user
4. What is outside version 1? — explicit non-goals and deferrals
5. How will we know it works? — measurable acceptance criteria

Additional instructions:
- Start with a short executive summary (problem + proposed solution).
- Write in plain language for a mixed technical and non-technical team.
- End with an Assumptions section for anything you inferred.
- If critical details are missing, ask up to 3 clarifying questions first.
  Otherwise, proceed and label assumptions.
```
