# Build loop cheatsheet

Compressed from Ai School live workshops. Use during a sprint.

## Build loop

1. **Define** the user and the painful job  
2. **Brief** — write what success looks like  
3. **Slice** — smallest vertical flow you can demo today  
4. **Build** in checkpoints (UI → one complete flow)  
5. **Verify** — run it · fix · don’t trust the model blindly  

## Vocabulary (quick)

| Term | Meaning |
|------|---------|
| **Prompt** | The work brief |
| **Context** | What the model can see (files, chat, rules) |
| **Agent** | Model + instructions + tools + loop |
| **Diff** | What changed in a file |
| **MVP** | Smallest thing that proves the idea |

## Safety rails

- Clean folder + **Git**  
- Review plans, commands, and diffs  
- **No secrets** in source  
- Run lint / build / the real user flow before you demo  

## Keep the MVP small

For a short demo you need: **one user · one action · one visible result**.  
Store listing, full monetization, and polish can wait until the core flow works.
